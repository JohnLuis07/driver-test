# Alpha 03 rendering recovery

## Review and evidence

Alpha 02 increased push-descriptor backing and snapshot capacity from 32 to 160 internal records and checked counts at descriptor updates and graphics/compute meta saves and restores. It returns early only when a push update cannot fit and marks the command buffer failed with `VK_ERROR_UNKNOWN`. That path logs the offending count. The meta guards skip unsafe memory accesses and mark the same error. Legal layouts still execute their full copies. Alpha 02 also logged Android swapchain setup failures. Those patches left GPU submission, framebuffer operations, texture lifetime, and Vulkan capability reporting intact. The device report confirms the SIGSEGV stopped and the screen stayed black.

The Alpha 01 log showed failed swapchain creation. In the pinned Peanuts source, `vka_present.c:swap_create` returns failure and the presentation caller returns before acquire or submit when there is no swapchain. Other game work can still be recorded. Alpha 02 supplied no new device log establishing which stage failed in its run. The exact last stage producing valid pixels on the Infinix is unknown.

The old ICD Android WSI implementation created a swapchain from imported AHBs, waited on the whole device, then copied locked AHB bytes into a native window. It returned success even if the wait, lock, copy or post failed. The Android platform loader can also use the parallel `VK_ANDROID_native_buffer` path. That path discovered image layout through gralloc but imported descriptor zero from the native handle, which need not be the FD that owns the image planes. Both paths were present before Alpha 02. [AOSP Vulkan WSI](https://source.android.com/docs/core/graphics/implement-vulkan)

## Alpha 03 changes

- The ICD WSI creates ordinary Vulkan render images and reuses Mesa's CPU WSI command buffers for a GPU copy into a mapped host-coherent staging buffer. This route removes AHB import from ICD swapchain creation. Existing Vulkan rendering and copy commands still execute on the GPU. Mesa orders the copy after the present wait semaphores, transitions the image for transfer and back, and adds a transfer-write to host-read barrier. The Android present callback checks the fence before inspecting staging pixels.
- The Android window copy checks format, dimensions, stride, geometry, and post results. BGRA is converted to the native RGBA order. Opaque composition uses RGBX or explicitly fills destination alpha. Successful image acquisition and the first four posted frames log image index, format, size, fence success and exact nonblack RGB pixel counts. A post success means Android accepted the buffer, while proof of visible display still requires the phone.
- PanVK's platform native-buffer path imports the gralloc-selected plane FD and rejects unsupported disjoint imports. It duplicates the borrowed FD through the existing memory helper. The caller's handle remains owned by Android. The deferred ANB and AHB paths assemble temporary `pNext` chains on local create-info copies, so retry and cleanup cannot see pointers to expired stack nodes. This path still requires a trusted mapper layout. It continues to report import failure if that metadata is unavailable.
- Alpha 02 descriptor fixes remain active. Alpha 02's WSI logging patch is superseded by the new WSI path.

No changes were made to shader translation, GPL, NIR, AFBC on ordinary render targets, or the D24/S8 capability mask. Peanuts' rescale fallback clears images when a scaled depth/stencil transfer lacks the required blit features. Using resolution scale 1.0 isolates that path. An aspect-aware scaled depth/stencil implementation or a compatible application fallback requires its own regression tests. An equal-size transfer can use an image copy with separate depth and stencil aspects, but that does not implement scaling.

Faux123 v1.1.8 uses the same pinned Mesa base, different private changes, and an older NDK according to its published metadata. Its public binary exports the same Android HAL and ICD entry points and imports the same Android library set. Binary symbols confirm it has both WSI routes. Its device success remains the A/B control. [Faux123 source and build disclosure](https://github.com/faux123/panvk-faux123-driver-ace#where-the-driver-comes-from)

## Validation

Codespaces cross-builds the ICD and checks Android ARM64 ELF, loader symbols, dependencies, ZIP import and checksums. Upstream offscreen triangle, depth/stencil, texture and FD import probes were cross-compiled for ARM64. The Android surface test was cross-compiled as a JNI library. On x86-64 Mesa Lavapipe, the triangle readback passed and the depth/stencil probe passed 10 cases with one unsupported-format skip. The texture probe could not create a device with its requested extension set there. None of these steps executes the Infinix GPU. Do not treat a desktop rendering result or a successful ZIP import as device validation.

On the phone, import Alpha 03 into Peanuts and use the [conservative settings](alpha02-investigation.md#next-comparison), especially resolution scale 1.0. Leave Alpha 01 and Alpha 02 installed. Compare the same save against faux123. If Alpha 03 is black, return the first swapchain, acquire, submit, present, mapper and kbase lines. If the CPU WSI path is used, the readback logs identify whether the final submitted image reached CPU memory and contained nonblack pixels. If the platform loader uses its own WSI path, the CPU WSI log lines will be absent and the mapper diagnostics are the relevant evidence.

For a standalone surface test, use PanProbe's driver import to select the Alpha 03 ICD extracted from the ZIP and run **swapchain_lifecycle**. It draws a visible triangle and exercises acquisition, submission, present, and recreation. Run the offscreen triangle, texture, depth/stencil and external memory probes through PanProbe where available. A shell run of the supplied standalone benchmarks can be blocked by the shell's kbase permissions. The JNI library is a build-time validation artifact for PanProbe and requires its app harness. The GPL extension query is not a pipeline link test. [Pinned PanProbe source](https://github.com/zenithblue-oss/panvk-kbase-android/tree/5b87b74d3e2580d5816e7f2c629f6f016a462f28/apps/panvk-test)

For deeper analysis, retain Peanuts replay statistics and kbase fault messages. The Alpha 03 logging covers swapchain creation, acquired indices, fence waits, CPU readback and window post. Full draw, barrier, semaphore and pipeline creation traces were not added. Use the diagnostic ZIP and matching DWARF if a new native crash occurs. Roll back by selecting Alpha 02 or faux123 in the game's driver picker and restarting Peanuts.
